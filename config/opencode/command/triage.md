Triage the GitHub items described by $ARGUMENTS. Read the complete issue or PR,
relevant discussion, labels, code, and tests before recommending a disposition.
Distinguish bugs, enhancements, missing information, agent-ready work,
human-owned work, and requests that should not proceed.

Before recommending new work, search for an existing implementation, duplicate
request, or prior rejection. Preserve prior triage conclusions and do not ask
questions that the issue history already answers.

Read-only listing and analysis need no confirmation. Before adding labels,
posting comments, closing items, or creating repository files, summarize the
mutation and ask once unless the user explicitly requested that exact change.
Prefix AI-authored GitHub comments with:

> *This was generated by AI during triage.*

Verify concrete claims when feasible, but match effort to risk. Do not force a
full design interview or reproduction for simple classification. Preserve prior
decisions and avoid assigning issues to the user unless explicitly requested.
