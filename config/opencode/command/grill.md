---
description: Stress-test a plan or design through focused questions
---

Stress-test the plan or design in $ARGUMENTS. If no subject was supplied, ask
what should be examined.

Inspect the environment for factual answers instead of asking the user. Ask
only questions whose answers materially change behavior, architecture, safety,
cost, or scope. Work in short rounds, include a recommended answer, and track
decisions and unresolved risks. Ask questions whose prerequisites are settled
before questions that depend on them, but do not try to visit every theoretical
branch.

This command is for discussion. Do not implement the plan or modify project
documentation unless the user explicitly asks.
